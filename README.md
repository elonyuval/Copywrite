# קופירייט · סביבת עבודה לקריאייטיבים

מערכת פרטית לשני אנשים לכתיבה ולניהול של תסריטי וידאו למותגי איקומרס:
מותגים ← מוצרים ← קריאייטיבים, עם כמה הוקים לכל תסריט, עריכה משותפת בזמן אמת, חקר לקוח, עוזר AI, אישורים, קבצים והיסטוריה.

## ארכיטקטורה בקצרה

| שכבה | בחירה | למה |
|---|---|---|
| שרת | Node 22 + Express + [Hocuspocus](https://tiptap.dev/docs/hocuspocus) על פורט אחד | שירות אחד לתחזוקה: API, WebSocket ו־frontend |
| מסד נתונים | Postgres | אפשר להשתמש בכל Postgres מנוהל: Neon, Supabase, Railway, Render |
| עריכה משותפת | Yjs (CRDT) + TipTap | מיזוג שינויים ברמת התו, בלי "האחרון מנצח" |
| קבצים | דיסק / volume, דרך נתיב מאובטח בלבד | `server/storage.ts`. אפשר להחליף ב־S3/R2 |
| AI | OpenAI Responses API + Structured Outputs, מהשרת בלבד | המפתח לא מגיע לדפדפן |
| לקוח | React + Vite, עברית RTL | |

### מבנה הנתונים של קריאייטיב
לכל קריאייטיב יש מסמך Yjs אחד (`shared/script.ts`):
- `hooks`: מפה של ההוקים (סדר, מחיקה רכה). הטקסט של כל הוק נשמר ב־`hook:<id>`.
- `lead`, `body`, `cta`: **נשמרים פעם אחת** ומשותפים לכל ההוקים.
- `shooting`: הוראות צילום. לא מוקראות ולא נספרות בזמן ההקראה.
- `research:<section>`: חקר הלקוח, עם סימון מקור לכל פריט: מסרנו / עם מקור / השערה / דוגמה של AI.

סטטוס, אישורים, תגובות, קבצים, שיחות AI, הצעות, העדפות ויומן פעולות נשמרים בטבלאות Postgres (`server/migrations`).

### שמירה ומצבי חיבור
- השרת שומר את המסמך ל־Postgres כ־1.2 שניות אחרי הפסקה בהקלדה, ולכל המאוחר כל 8 שניות.
- אחרי כל שמירה מוצלחת השרת משדר את ה־state vector. הדפדפן מציג **"נשמר"** רק כשכל השינויים שלו כבר במסד הנתונים.
- המצבים המוצגים: מתחבר / שומר / נשמר / השמירה מתעכבת / השמירה נכשלה / מנותק / מנותק עם שינויים שלא נשמרו.
- כשאין חיבור אפשר להמשיך לכתוב. השינויים מסתנכרנים כשהחיבור חוזר, וסגירת הלשונית עם שינויים שלא נשמרו מציגה אזהרה.
- גרסאות היסטוריה נשמרות אוטומטית (כל ~10 דקות של שינויים), וגם בשמירה ידנית, באישור, לפני שחזור ולפני החלת הצעת AI.

## הרצה מקומית

דרישות: Node 22 ו־Postgres.

```bash
npm install
cp .env.example .env              # למלא DATABASE_URL ו-SESSION_SECRET
npm run dev                       # שרת על 3000 + Vite על 5173
```
נכנסים ל־http://localhost:5173. המשתמש הראשון מקים את סביבת העבודה, ואז מגדרות יוצרים **קוד הזמנה** לשותף/ה.

הרצה כמו בייצור:
```bash
npm run build && npm start        # הכול על http://localhost:3000
```

## פריסה (לשני מחשבים נפרדים)

צריך שלושה דברים: שרת Node שרץ ברציפות (בגלל WebSocket), Postgres, ודיסק קבוע לקבצים.
מתאים ל־Railway, Render, Fly.io או כל VPS. מצורף `Dockerfile`.

1. יוצרים מסד Postgres ומעתיקים את ה־connection string.
2. פורסים את ה־Dockerfile ומחברים volume קבוע ל־`/data`.
3. מגדירים משתני סביבה:
   - `DATABASE_URL`: חובה.
   - `SESSION_SECRET`: חובה. מחרוזת אקראית ארוכה.
   - `SETUP_TOKEN`: חובה בייצור. בלעדיו אי אפשר ליצור את המשתמש הראשון.
   - `PUBLIC_URL`: הכתובת הציבורית, למשל `https://copy.example.com`.
   - `OPENAI_API_KEY` ו־`OPENAI_MODEL` (ברירת מחדל: `gpt-5.5`): ל־AI.
   - `NODE_ENV=production`
4. נכנסים לכתובת, מקימים את המשתמש הראשון עם ה־`SETUP_TOKEN`, ויוצרים קוד הזמנה לשותף/ה.

המיגרציות רצות אוטומטית בעליית השרת.

## חיבור AI

- נדרש **מפתח API של OpenAI** (platform.openai.com) עם אמצעי תשלום. השימוש מחויב בנפרד ממנוי ChatGPT.
- בלי מפתח המערכת עובדת במלואה חוץ מ־AI, ומציגה מצב "לא מוגדר" עם הוראות. אין מצב דמו.
- לעוזר **אין** גישה לשיחות או לזיכרונות בחשבון ChatGPT. מידע משם זמין רק אם מעתיקים אותו ל"העדפות ושיטות עבודה".
- ההקשר שנשלח למודל נבנה **בשרת** מתוך מסד הנתונים והמסמך החי: תיק המוצר, ההעדפות הפעילות, המחקר, התסריט וההוק הנבחר, ו־30 ההודעות האחרונות בשיחה עם שם הכותב.
- הצעה לשינוי נשמרת יחד עם הטקסט שה־AI ראה. אם הטקסט השתנה מאז, "החלה" נחסמת גם בממשק וגם בשרת. "הוספה כהוק" עדיין אפשרית.
- הצעות יזומות נשלחות רק אחרי 12 שניות בלי הקלדה ושינוי של לפחות כ־60 תווים, לכל היותר פעם ב־90 שניות. השרת חוסם בקשה כפולה לאותו תוכן.
- מגבלות: 40 בקשות AI ל־10 דקות לכל משתמש, ובקשה אחת בכל רגע לכל שיחה. שגיאות כמו מכסה, מפתח שגוי, מודל לא זמין או timeout מוצגות בעברית.

## אבטחה

- סיסמאות מוצפנות ב־scrypt. סשן נשמר בעוגיית httpOnly + SameSite=Lax, ובמסד נשמר רק hash של הטוקן.
- **כל** נתיב API, חיבור WebSocket ופעולת AI בודקים בשרת שהמשתמש חבר בסביבת העבודה של הפריט. פריט מסביבת עבודה אחרת מחזיר "לא נמצא".
- בקשות POST, PATCH ו־DELETE ממקור זר נחסמות (בדיקת Origin).
- קבצים מוגשים רק דרך `/api/files/:id` אחרי בדיקת הרשאה. HTML ו־SVG יורדים כקובץ ולא מוצגים בדפדפן.
- `OPENAI_API_KEY` קיים רק בשרת. יש בדיקה אוטומטית שהמפתח לא מופיע ב־bundle של הדפדפן.

## הכנה לחיבור חיצוני (API / MCP)

ב"הגדרות" אפשר ליצור **טוקן לקריאה בלבד** לסביבת העבודה:
```
GET /api/ext/v1/brands
GET /api/ext/v1/products
GET /api/ext/v1/products/:id/creatives
GET /api/ext/v1/creatives/:id           # תסריט + גרסה משולבת לכל הוק
GET /api/ext/v1/creatives/:id/history   # יומן פעולות + גרסאות
Authorization: Bearer <token>
```
שרת MCP עתידי יכול לעטוף את הנתיבים האלה. **שום חיבור חיצוני, כולל ChatGPT, לא פעיל עד שמגדירים אותו במפורש.**

## זמן הקראה
כל ערכי הקצב מרוכזים ב־`shared/readingTime.ts`: איטי 120, רגיל 150 ומהיר 180 מילים לדקה.
החישוב מתבצע מקומית ולא דורש AI. הוא כולל רק את **ההוק הנבחר + ליד + גוף + קריאה לפעולה**.

## בדיקות

```bash
npm run typecheck
npm test                          # בדיקות יחידה: מבנה המסמך, זמן הקראה, מיזוג CRDT
npm run test:e2e                  # 16 תרחישים מקצה לקצה: שני משתמשים, דפדפן אמיתי, Postgres אמיתי
```
בדיקות ה־e2e מריצות שרת נקי על מסד `copywrite_test` (משתנה `TEST_DATABASE_URL`) ושרת OpenAI **מדומה** (`tests/e2e/mock-openai.mjs`). המטרה היא לבדוק מה נשלח למודל ואיך התשובות מטופלות. אם Playwright לא מוצא דפדפן, מגדירים `CHROMIUM_PATH`.

## מגבלות ידועות בגרסה הזו

- **הקלדה באותה נקודה בדיוק באותו רגע**, כשהשדה ריק: שום תו לא הולך לאיבוד והטקסט זהה אצל שניהם, אבל תו בודד עלול להופיע במקום אחר. בעריכה בו־זמנית במקומות שונים באותו שדה המיזוג תמיד מדויק.
- פריטי מחקר נערכים כשדה קצר. אם שניים עורכים **אותו פריט** ממש באותו רגע, השינוי האחרון של הפריט נשמר. התסריט עצמו, כלומר הוקים, ליד, גוף, קריאה לפעולה והוראות צילום, ממוזג ברמת התו.
- תיק המוצר נשמר כטופס עם בדיקת גרסה: אם השותף/ה שמר/ה בינתיים, השמירה נחסמת ומוצגים הנתונים העדכניים, במקום לדרוס.
- הגבלת הקצב נשמרת בזיכרון של השרת, כך שהמערכת מיועדת לשרת יחיד. זה מספיק לשני משתמשים.
- אין חיבור למטא ואין ניהול קמפיינים. זה מכוון.
